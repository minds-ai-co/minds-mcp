# Documentation publishing model

The Markdown files in `reference/` are the canonical source for maintained Minds
MCP integration documentation.

## Maintained documentation

- Read the Docs builds `reference/` with MkDocs.
- [GitBook](https://minds-1.gitbook.io/minds-mcp/) synchronizes `reference/`
  from this repository with Git Sync.
- The [MCP setup generator](https://minds-mcp-setup-generator.netlify.app/) is a
  thin interactive utility. It links back to the maintained setup guide instead
  of duplicating the reference content.
- Future documentation hosts must import or build from `reference/`; do not create
  a second manually maintained copy.

Navigation files and platform configuration may differ, but product behavior,
setup guidance, tool descriptions, research scope, and examples must be edited in
`reference/` first.

## Generated from the live server

The public inventory (`https://getminds.ai/api/public/mcp`) supplies curated
advertised tools, hidden tools, aliases, scopes, and the deployed server version.
The server card (`https://getminds.ai/.well-known/mcp/server-card.json`) supplies
full input/output schemas and annotations. Both are generated by the webapp.
`scripts/sync-mcp-surface.mjs` checks that the sources agree before regenerating:

- the tools table in `README.md` between `<!-- tools:start -->` and
  `<!-- tools:end -->`;
- `reference/tools.md`, including hidden tools, aliases and access scopes;
- `reference/workflow.md`, with full production behavior descriptions and input
  guidance copied from each advertised tool's schema;
- `integrations/microsoft-mcp/mcptools.json`;
- the `version` of every plugin and extension manifest, using the deployed
  server version without moving a package version backwards.

Do not edit these generated sections by hand. Refresh them with:

```bash
node scripts/sync-mcp-surface.mjs
node scripts/sync-mcp-surface.mjs --check
node --test scripts/__tests__/*.test.mjs
node integrations/microsoft-mcp/scripts/validate.mjs
```

The `Sync MCP surface` workflow runs every six hours and can also be run manually
or triggered with `repository_dispatch` event type `mcp-surface-changed` after a
production deployment. It opens or updates one PR on
`automation/sync-mcp-surface`, changing only generated artifacts. After checking
that the bot PR contains exactly the generated bytes validated in that run, it
squash-merges automatically and requests a GitHub Pages rebuild. Human PRs,
unexpected files, changed PR revisions, and a changed base branch are refused. No Minds credentials
are needed; the workflow uses the repository's `GITHUB_TOKEN` for its PR.

The workflow validates regeneration and the Microsoft package before opening a
PR. GitHub can require approval for PR workflows started by `GITHUB_TOKEN`, and
its merges do not trigger normal push workflows, so validation runs in the sync
job and GitHub Pages publication is requested explicitly. No bypass flags are
used: repository merge requirements still apply. Human-authored PRs also run `--check`,
which fails on generated drift or a handwritten page naming a non-advertised tool.
An unavailable source, inconsistent deploy snapshot, or stale handwritten recipe
fails the sync job and prevents automatic publication. Detailed tool behavior is
generated directly from server descriptions and schemas, so routine behavior
changes need no separate prose edit. The cookbook contains general research
examples; entirely new research strategies are not inferred from tool metadata.

Portal submissions and immutable GitHub/Zenodo releases are separate from this
sync. Registry publication is owned by the webapp release workflow.

## Platform landing pages

`docs/` and `cloudflare-pages/` are intentionally platform-specific landing and
compatibility surfaces. Their visual design may differ. Keep their technical
content compact, link into the maintained setup/reference material, and avoid
turning either surface into an independent manual.

## Versioned archives

GitHub Releases and Zenodo preserve versioned snapshots. They do not track every
documentation commit. When an archived file changes materially, publish a new
release and Zenodo version instead of replacing the historical snapshot.

## Link rules

- Use `https://getminds.ai/mcp` only when identifying the Streamable HTTP
  transport endpoint.
- Send normal browser visits to `https://getminds.ai/mcp/setup`.
- Use the shared content campaign:
  `utm_source=content&utm_medium=content&utm_campaign=content-seo-mcp-reference`.
- Use content-based `utm_content` values rather than host-specific values so the
  same Markdown remains valid on every documentation host.
